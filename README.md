# Binance Square Bot — Reach Edition

Это версия бота с переработанной контентной архитектурой. Технический анализ и расчёт уровней остались кодовыми и проверяемыми, но публикации больше не собираются как бесконечная лента вида `$COIN — LONG/SHORT`.

## Что исправлено

Бот выбирает не только монету и направление, но и **редакционный формат**, авторскую подачу и подходящий тип изображения. В проекте реализованы:

- 15 форматов: ожидание подтверждения, история уровня, два сценария, риск-мемо, журнал трейдера, разбор индикатора, рыночный контекст, data-brief, торговый план, контрарный взгляд, ошибка трейдера, протокол исполнения, «сигнал ≠ сделка», карта ликвидности и продолжение прошлой идеи;
- 8 визуальных семейств: headline, data, indicator, risk, journal, split-scenario, level-map и clean chart; дополнительные context/follow-up варианты включаются при наличии данных;
- заголовки, построенные вокруг последствия, риска или решения, а не вокруг служебной метки LONG/SHORT;
- четыре авторских голоса: `analytical`, `calm`, `direct`, `contrarian`;
- нормализация заголовков между разными тикерами, поэтому одинаковое начало по BTC, ETH и SOL не считается новым;
- постоянная память форматов, визуалов, заголовков, CTA и смыслового сходства;
- Mistral только для редакционной подводки. Цены, направление, индикаторы, уровни и R/R вставляет и проверяет Python-код;
- адаптивное медиа: пост получает карточку или график в зависимости от своей идеи;
- безопасный локальный fallback, если Mistral недоступен.

## Быстрая установка

Требуется Python 3.11+ и Node.js с `npx`.

```bash
python -m venv .venv
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установите зависимости и Binance Square skill:

```bash
pip install -r requirements.txt
npx skills add https://github.com/binance/binance-skills-hub --skill square-post -y
```

Создайте конфигурацию:

Linux/macOS:

```bash
cp env.example .env
```

Windows PowerShell:

```powershell
Copy-Item env.example .env
```

## Первый безопасный запуск

В `.env` сначала оставьте:

```env
DRY_RUN=1
CONTENT_MODE=deterministic
```

Затем выполните:

```bash
python config_check.py
python self_test.py
python repetition_test.py
python preview_gallery.py
python main.py
```

`preview_gallery.py` создаёт каталог `preview_output` с восемью разными изображениями, контактным листом и примерами текстов. Он не обращается к Binance, Mistral или модулю публикации.

`main.py` в режиме `DRY_RUN=1` получает рыночные данные, выбирает реальный сетап, собирает лучший пост и печатает его, но не публикует.

## Включение реальной публикации

В `.env` укажите ключ Binance Square и переключите безопасный режим:

```env
SQUARE_API=ваш_ключ
DRY_RUN=0
```

Для AI-подачи дополнительно:

```env
CONTENT_MODE=ai_first
MISTRAL_API=ваш_ключ_mistral
```

Перед первым реальным запуском:

```bash
python config_check.py --publishing
python main.py
```

Ключи не записываются в тексты, изображения или журналы. В дочерний процесс публикации ключ передаётся через окружение.

## Главные настройки охватов

### Авторский голос

```env
AUTHOR_VOICE=analytical
```

Доступны:

- `analytical` — системный аналитик, решение по связке факторов;
- `calm` — спокойный автор, больше акцента на ожидании;
- `direct` — короткая и жёсткая подача;
- `contrarian` — поиск слабого места очевидного сценария.

Начать лучше с `analytical`. Голос меняет авторские ремарки, но не факты и уровни.

### Варианты и антидубликат

```env
POST_VARIANTS=16
MAX_POST_SIMILARITY=0.52
MIN_POST_QUALITY=78
POST_MEMORY_FILE=post_memory.json
```

Каждый запуск собирает до 16 полноценных кандидатов. Публикуется только валидный вариант с лучшим сочетанием качества и новизны.

`post_memory.json` **нельзя удалять между запусками**. Без него бот забудет предыдущие форматы, заголовки и формулировки. Для контейнера или панели хостинга разместите файл на постоянном диске и укажите абсолютный путь в `POST_MEMORY_FILE`.

Порог `0.52` откалиброван на стресс-тесте из 150 последовательных публикаций. Снижать его можно, но слишком низкое значение будет блокировать нормальные посты, потому что блоки входа, целей и стопа обязаны повторять торговую структуру. Повышать выше `0.60` не рекомендуется.

### Изображения

```env
PUBLISH_IMAGES=1
PUBLISH_MEDIA_MODE=adaptive
CARD_WATERMARK=PozitiveHero
CHART_WATERMARK=PozitiveHero
```

`adaptive` — основной режим. Истории, риск-мемо, data-brief и сценарии получают отдельные карточки; посты про уровни и структуру получают графики.

Дополнительные режимы:

```env
PUBLISH_MEDIA_MODE=card
PUBLISH_MEDIA_MODE=chart
PUBLISH_MEDIA_MODE=both
PUBLISH_MEDIA_MODE=none
```

`both` создаёт два изображения и нужен только при осознанном выборе. Для обычной ленты лучше `adaptive`: один сильный визуал выглядит чище.

### Mistral

```env
CONTENT_MODE=ai_first
AI_VARIANTS=6
AI_TEMPERATURE=0.58
```

Mistral получает закрытый каталог разрешённых фактов и возвращает только короткую подводку, авторское объяснение, вопрос и идентификаторы фактов. Любая неизвестная цифра, обещание прибыли, новость, инсайд или выдуманная причина движения отклоняет вариант.

Если API недоступен или возвращает некорректный JSON, локальный редакционный движок продолжает работу.

## Что проверяется перед публикацией

- точные `Вход`, три цели, `Стоп-лосс` и `R/R`;
- совпадение направления LONG/SHORT с рассчитанным сигналом;
- наличие точки отмены и запрет усреднения за стопом;
- 1–3 упоминания `$TICKER`;
- отсутствие неизвестных чисел и неподтверждённых утверждений;
- длина, читабельность, заголовок, человеческий голос и формат;
- правила вопроса аудитории для конкретного типа публикации;
- не более двух хэштегов;
- смысловое сходство с предыдущими постами;
- повтор редакционного и визуального формата.

## Диагностика

```bash
python config_check.py
```

Проверяет режимы, числовые параметры, доступность файлов памяти и истории. Значения ключей не выводятся.

```bash
python config_check.py --publishing
```

Дополнительно требует Square API key и установленный `square-post` skill.

При проблеме включите:

```env
LOG_LEVEL=DEBUG
DRY_RUN=1
```

## Важное ограничение

Эта версия устраняет основные технические причины однотипной ленты и повышает вероятность открытия и взаимодействия с постом. Она не может гарантировать конкретное количество просмотров: распределение зависит от состояния аккаунта, аудитории, актуальности выбранной монеты и алгоритмов Binance Square.
